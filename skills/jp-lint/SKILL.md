# jp-lint

書き終えた日本語の文書を検査して、問題の箇所を書き換える。目的は、書き手の意味を変えずに、読み手の負荷を下げること。

辞書の検査は速いが、部分一致の誤検出がある。語の置き換えは、検出された文の文脈を読んで決める。

## 規範を読む

検査の前に、文章の規範を読む。規範は `references/guides/` にある。

`guides/PRINCIPLES.md` は約 800 行あるので、全文は読まない。冒頭の表の「check / rewrite 実行 (jp-lint)」の行にある節だけを読む。

続けて、文書の種類に合う file を 1 本読む。

| 文書の種類 | 読む file |
|---|---|
| PRD / Design Doc / 仕様書 | `guides/design-doc-protocol.md` |
| PR 本文 | `guides/pr-description.md` |
| issue | `guides/gh-issue.md` |
| 上のどれでもない長文 (見出しが複数あるか 1,000 字を超える) | `guides/long-form-doc.md` |

人が読む文書 (Design Doc / 長文 / 手順書) を書き直すときは、表の file に加えて `guides/document-design.md` の章立て・書き直し・図の節も読む。

規範に、この skill に同梱していない command や file の名前が含まれることがある。それらは無視する。

## 手順

1. 検査する: 同梱の script を実行する。`<skill dir>` はこの `SKILL.md` があるディレクトリ。

   ```bash
   bash <skill dir>/scripts/jp-quality-lint.sh <file...>
   bash <skill dir>/scripts/jp-quality-lint.sh --strict <file...>   # 荒い比喩語と無理やりの短縮も見る
   ```

   `block` は書き換える対象、`warn` は文脈を読んで判断する対象。終了コードは block が 1 件でもあれば 1。
   「確認済」のような省略形は `--strict` でしか検出できない。

   script は code block を検査しない。ただし ```` ```suggestion ```` の block は相手の文書へそのまま入る文なので、中身を別の file に書き出して同じ script にかける。手順 5 の見直しでも本文と同じく読む。

   ```bash
   awk '/^```suggestion/{f=1;next} /^```/{f=0} f' <file> > /tmp/jp-lint-suggestion.md
   bash <skill dir>/scripts/jp-quality-lint.sh --strict /tmp/jp-lint-suggestion.md
   ```

   suggestion の hit が相手の文書に元からある語なら見送る。書き換えると相手の文書の用語が変わる。

   Notion などの外部 page が対象なら、page を取得して本文の text を一時 file に書き出し、同じ script にかける。修正は page の更新機能で行い、修正後にもう一度取得して反映を確かめる。

2. 文脈を判定する: hit した語ごとに前後の文を読み、書き換えるか見送るかを決める。見送るのは、識別子や固有名詞への部分一致、引用文、別の意味で使った語。見送りには理由を 1 行付ける。
3. 書き換える: 書き換えると決めた箇所だけを、最小の差分で書き換える。語だけを置換せず、検出語を含む文を単位に書き換える。置換候補は書き換えの方向を示すもので、貼り替える対象ではない。文書にない事実・数値・理由は書き加えない。
4. 文の組み立てを点検する: 辞書で検出できない型なので、hit がなくても点検する。`guides/PRINCIPLES.md` の「「状況 → 読み手の結果 → 対処」の順で書き、対処は具体的な動作で書く」と「1 文の述語に時点を 2 つ掛けない」の 2 節を読んで適用する。見る型は 3 つある。
   - 対処から始まる文 (「〜しているのは、〜だからです」)。状況、読み手に起きること、対処の順に書き換える
   - 1 文の述語に時点や主体が 2 つ掛かる文。2 文に分ける
   - 参照先との間に文・段落・表が入った指示語 (「3 行目」「上の〜」「5〜9 の手順」「この状態」など)。指示語は同じ文か直前の 1 文だけを受けるので、離れていれば指している名詞に書き換える
   読み違えの原因になる文だけを最小の差分で書き換える。
4.5. 主張の大きさを確かめる: 対象が読み手の判断に使う外向きの文章 (記事 / Design Doc / PR 本文 / 提案資料) のときだけ行う。`guides/PRINCIPLES.md` の「主張は目的と観測した事実の大きさで書く」を読み、次の 6 つを探す。書き手に固有の数値や運用、手段や数値目標だけの機能説明、言い切った効果、断定した目標、判断を変えない前置き、列の形が違う手順の表。効果の大きさや固有の数値が事実かは書き手しか知らないので、言い換えの案を示し、事実の確認が必要な箇所は書き手に確かめる。
4.6. 箇条書きに開く: script の hit が無い file も対象にする。`guides/PRINCIPLES.md` の「箇条書き階層化」の「段落から箇条書きに開く条件」を読んで適用する。
4.7. 媒体の規則を適用する: 「規範を読む」で決めた種類ごとの file にある、表記・装飾・公開前 checklist の項目を 1 つずつ対象の文書と照合する。読むだけで終えず、項目ごとに該当の有無を判定する。あわせて、script が検出しない表記の揺れを次の command で探す (英数字と日本語の間の半角 space の欠け、全角と半角の括弧の混在)。

   ```bash
   grep -nE '[一-龥ぁ-んァ-ヶ][A-Za-z0-9]|[A-Za-z0-9][一-龥ぁ-んァ-ヶ]' <file> | grep -v '`'
   grep -n '(' <file> | grep '（'; grep -c '(' <file>; grep -c '（' <file>
   ```

   半角と全角の括弧が両方あれば、多い側の表記に統一する。code 識別子・URL・固有名詞の中の表記は対象外。
5. 見直しをする: 下の「見直しの手順」に従う。点数は付けない。
6. 再検査する: script をもう一度実行し、block が見送り分だけになったことを確かめる。

## 見直しの手順

観点の本文は `guides/PRINCIPLES.md` の「見直し5観点」にある。この節には適用する順番だけを記載する。

先に文書の目的と読み手を決める (`guides/PRINCIPLES.md` の「媒体別構造」)。技術文書では、判断の根拠と前提を優先する。文は字数ではなく、読み違えが起きる境界で分ける。

1. 文書全体を確かめる: 局所の文や語より先に、`guides/PRINCIPLES.md` の「文書全体の読みやすさ」を適用する。並列する事実や手順が段落の中に詰め込まれていれば、箇条書きや表に開く
2. 骨組みを確かめる (見出しがある文書だけ): 見出しの階層と、各節の主張だけを取り出して、構造の破綻を先に探す
   - 結論と理由を担う節を特定し、概要・比較・推奨・残課題に同じ主張が分散していないか確かめる
   - 読後の判断や行動を変えない節は、削除・統合・詳細への移動を検討する
   - 構造の問題が未対応なら、局所の文だけを書き換えて終えない
3. 局所を確かめる: 「見直し5観点」と「文単位の品質規約」「圧縮文を開く」を適用する。読み違え、主語と述語の不対応、論点の飛躍、重複を文脈で判断する

変更するのは、読み違い・判断の阻害・論理の断絶につながる箇所だけ。意味が明確な英語の用語や類義語を好みで置き換えず、再点検のたびに新しい変更を作らない。書き換えの前後で、事実・時制・因果関係・書き手の評価が一致することを優先する。

## 報告

- 1 行目に、読んだ規範 (`PRINCIPLES.md` の節と、種類ごとの file) を並べる
- 辞書の検査は「書き換え N / 見送り N (理由) / 該当なし」の 1 行で返す
- 箇条書き (手順 4.6) は「箇条書き: 組み替え N / 該当なし」の 1 行を返す
- 媒体の規則 (手順 4.7) は「媒体の規則: 修正 N / 該当なし」の 1 行を返す
- suggestion の block を検査したら、本文とは別に「suggestion: 書き換え N / 該当なし」の 1 行を返す
- 見直しで変更したら、文書全体に関わる要点を 1 文で返す。変更がなければ「読み違いにつながる問題は見つからなかった」とだけ返す
- 検証の失敗や未解決の問題は省かない

報告の例:

> 辞書: 書き換え 3 / 見送り 1 (code 識別子への部分一致)。文の組み立て: 書き換え 1。見直しで、結論を「概要」の節へまとめました。

## 失敗したとき

| 症状 | 見分け方 | 対処 |
|---|---|---|
| 修正前後で hit の比較が合わない | 比べた 2 file の置き場所が違う (置き場所で検査の対象や判定が変わる) | 修正前の版を同じディレクトリに別名で置き、両方を script で検査する。指摘の行を内容で比べ、増えた指摘だけを確かめる |
| 言い換えで意味が変わった | 修正前後の文で、事実・時制・因果関係・書き手の評価のどれかが一致しない | その箇所は元の文に戻して見送りに数え、理由を 1 行付ける |
| block が辞書の誤検出 | hit が code の識別子・固有名詞・引用文への部分一致 | 見送りに数える。辞書の誤りなら、`references/NG-DICTIONARY.md` への修正案を報告に添える |
| 再検査で block が見送り分より多い | 手順 6 の再検査で、手順 2 の見送り件数を超える hit がある | 超えた hit を手順 2 から判定し、block が見送り分だけになってから報告する |

## 守ること

- hit の一括置換をしない。部分一致の誤検出まで書き換えてしまうため
- warn の語を無差別に書き換えない。断定語や英語の専門語は、書き換えると文意が変わることがある。迷ったら維持する
- 書き手の評価、時制、因果関係を変えない
- 辞書の語を例として引用する文書では、引用する語をバッククォートで囲む。囲んだ語は検査の対象外になる。囲まないと、使っている語として検出される

## 辞書

`references/NG-DICTIONARY.md` が辞書で、検査 script はこの file から語を読む。語を追加するときは、既存の項目名と書式をそのまま使う。項目名を変えると、検査が止まる。
