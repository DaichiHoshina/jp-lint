# jp-lint

書き終えた日本語の文書を検査して直す。目的は、書き手の意味を変えずに、読み手の負荷を下げること。

辞書の検査は機械的で速いが、部分一致の誤検出がある。語の置き換えは、検出された文の文脈を読んで決める。

## 手順

1. **検査する**: 同梱の script を実行する。`<skill dir>` はこの `SKILL.md` があるディレクトリ。

   ```bash
   bash <skill dir>/scripts/jp-quality-lint.sh <file...>
   bash <skill dir>/scripts/jp-quality-lint.sh --strict <file...>   # 荒い比喩語と無理やりの短縮も見る
   ```

   `block` は直す対象、`warn` は文脈を見て判断する対象。終了コードは block が 1 件でもあれば 1。
   「確認済」のような省略形は `--strict` でしか検出できない。

2. **文脈を判定する**: hit した語ごとに前後の文を読み、直すか見送るかを決める。見送るのは、識別子や固有名詞への部分一致、引用文、別の意味で使った語。見送りには理由を 1 行付ける。
3. **直す**: 直すと決めた箇所だけを、最小の差分で書き換える。語だけを置換せず、検出語を含む文を単位に書き換える。置換候補は書き換えの方向を示すもので、貼り替える対象ではない。文書にない事実・数値・理由は足さない。
4. **文の組み立てを見る**: 辞書で検出できない型なので、hit がなくても見る。
   - 対処から始まる文。「状況 → 読み手に起きること → 対処」の順に直す
   - 1 文の述語に時点や主体が 2 つ掛かる文。2 文に分ける
5. **推敲する**: 下の 5 観点で見落としを探す。点数は付けない。
6. **再検査する**: script をもう一度実行し、block が見送り分だけになったことを確かめる。

## 推敲の 5 観点

見出しのある文書は、局所の文より先に、見出しごとの主張に重複や食い違いがないかを見る。

| 観点 | 見ること |
|---|---|
| 読みやすさ | 読み違い・判断の阻害・論理の断絶の原因になる箇所だけ直す。好みの類義語置換はしない |
| 見やすさ | 見出しの階層、箇条書き、表が内容の型に合っているか |
| 結論の位置 | 結論が先頭にあるか |
| 根拠 | 主張が入力内の数値・事例で支えられているか。根拠がなければ作らない |
| 一貫性 | 用語が統一されているか、同じ内容の重複がないか |

変更するのは、読み違いにつながる箇所だけ。再点検のたびに変更を作る必要はない。

## 報告

- 辞書の検査は「直した N / 見送り N (理由) / 該当なし」の 1 行で返す
- 推敲で変更したら、文書全体に関わる要点を 1 文で返す。変更がなければ「読み違いにつながる問題は見つからなかった」とだけ返す
- 検証の失敗や未解決の問題は省かない

## 守ること

- hit の一括置換をしない。部分一致の誤検出を書き換えてしまうため
- warn の語を無差別に直さない。断定語や英語の専門語は、直すと文意が変わることがある。迷ったら残す
- 書き手の評価、時制、因果関係を変えない

## 辞書

`references/NG-DICTIONARY.md` が辞書で、検査 script はこの file から語を読む。語を足すときは、既存の項目名と書式をそのまま使う。項目名を変えると、検査が止まる。
